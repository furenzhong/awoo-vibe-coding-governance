# 安全审查附页

版本：v1.0，供确实涉及依赖、构建产物、凭据或秘密的审查按需引用。它补充 [AI 代码审查协议](AI_CODE_REVIEW_PROTOCOL.md)，不替代六步流程，也不要求所有项目逐项执行。

## 依赖可达性

| 包 / 版本 / 公告 | 静态存在位置 | 运行时可达及依据 | 受影响配置/功能 | 是否复现 | 结论与证据 ID |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

区分清单中存在、被构建包含、运行时可达和实际触发。说明平台、可选模块、默认配置、调用路径及缓解条件。只有静态命中时使用 `observed` / `inferred`，不要写成已利用或已触发；不能复现时保留 `unknown` 或 `partial`。

## 凭据与秘密

| 位置 | 秘密类型 | 是否为真实值/明文 | 是否进入构建产物、日志或网络 | 暴露面与轮换状态 | 处置、复验与证据 ID |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

仅在授权范围内记录定位和必要摘要，不把秘密值复制进审查记录或公开仓库。区分掩码展示与底层存储、源文件与打包产物、配置读取与实际外发。若发现真实凭据，记录安全处置入口和轮换状态，不在报告中复述凭据。

## 跨项目重复模式

| 模式及共同条件 | 项目/版本 | 已执行的反例 | 观察到的结果 | 共享修正及复验 |
|---|---|---|---|---|
|  |  |  |  |  |

只有两个或更多项目具有可比实现和证据时，才归纳为重复模式；相似命名或静态片段本身不足以证明同一缺陷。共享修正应回到协议、模板或工具的实际责任边界，并用独立样本复验。
