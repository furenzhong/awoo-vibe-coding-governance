# 文档治理规则

## 目的

让不同 AI、不同会话和不同执行工具能继续同一个项目，减少目标偏移、重复操作和未经验证的完成声明。文档是否有用，以这些结果衡量。

## 信息归属

| 信息 | 放在哪里 | 更新方式 |
|---|---|---|
| 稳定的项目规则、读取顺序 | AGENTS.md / 映射的 rules | 有规则变化才修改，入口保持短 |
| 用户确认的目标与验收条件 | 当前产品合同或最小任务说明 | 记录来源；变化时标明影响 |
| 当前阶段、已知事实、假设、下一步 | 映射的 status | 原位维护当前结论，事实链接到证据 |
| 未完成现场的导航、恢复入口 | 映射的 handoff | 更新接续指针，指向任务及各身份检查点，不复制任务状态 |
| 为什么作出选择、何时重新考虑 | 映射的 decisions | 追加决定与替代关系 |
| 一次委派的生命周期 | tasks_dir 中对应任务 | 一个任务一份状态，其他入口只链接 |
| 当时派发的依据、各身份停点、纠偏沟通事实 | 任务附属上下文记录 | 快照保留版本，检查点各自维护；区分纠偏记录、送达和采用 |
| 可重复使用的环境、访问途径和已验证操作方法 | 项目已有部署／操作说明 | 记录适用范围和验证时点；凭据只记获取位置；任务现场链接它 |
| 某版本实际运行、验证结果 | evidence_dir 或已有证据目录 | 留存原始记录，不倒改历史为通过 |
| 文档索引、上下文简报 | index / brief | 引用上面的权威来源，不另建进度副本 |

开发过程中的工作材料、当前权威、证据和归档材料具有不同的用途。工作材料用于推进问题，当前权威用于回答“现在是什么”，证据用于复核，归档材料用于追溯；不能把它们都塞进默认上下文。用户明确唤醒整理后，先更新唯一权威来源，保留约束、未决项、否决原因和证据，再标记被替代材料或按需归档。[文档生命周期](DOCUMENT_LIFECYCLE.md) 定义主动唤醒、压缩和清理边界；`python scripts/project_os.py inventory --target . --json` 只读报告声明和路径信号，不自动移动、合并或删除文件。

`project-os.json` 记录实际映射，已有项目不必改名或搬目录。映射只是导航与检查配置，不赋予外部执行权限。

## 三种信息与一个结论

- **要求**：用户已确认要实现什么。模型不能悄悄改变成功标准来让自己通过。
- **假设**：尚未验证的选择，写清如何验证和什么结果会推翻它。
- **观察**：在什么版本、环境、输入下，实际发生了什么，证据在哪里。
- **验收**：依据哪些要求和观察作出的判断。未覆盖的部分保持未验证。

“已实现”“某项检查通过”“服务已加载”“用户认可效果”分别表达。进程退出成功或 JSON 合法不能单独证明业务完成。历史测试通过也不能自动证明当前变更通过。

## 冲突处理

规则来源遵守宿主约束与用户当前要求。项目规范描述意图，代码和运行证据描述观察；两者不符是待解决的差异，不能以其中一个代替另一个。

先核对来源、时间、版本与适用范围，再修正唯一当前结论。历史记录保留，并注明被哪个新结论替代。不要在规则开头不断叠加“以下旧说明全部覆盖”的进度段落。

## 共享指令与主动维护

Codex、Claude Code 和其他能够读写项目文件的执行工具，应遵循同一份文档治理工作纪律。2026-10-09 用户确认：将这些约定明确写入共享指令，可以推动 AI 自主更新、记录并核对项目知识，减少切换执行者或对话时的误差。这个决定承接已有任务上下文与事件记录设计；实际恢复准确率和长期维护收益仍需观察，不能由规则文本推定。

三层职责分别是：`AGENTS.md` 要求模型主动提取有意义的变化并写回原来源；已采用的宿主事件接口保存实际可取得的输入、摘要和结果；恢复者核对这些线索、当前决定及真实现场，再继续工作。共享规则维护、原生捕获成功和实际接续通过分别留证。

重要确认、纠偏、否决理由、证据和未完成现场，应在形成且仍可查证时保存；下一步依赖变化时先写回对应来源，否则在本轮结束前保存。无需等用户再次说“记入文档治理”，也不等自动压缩或换会话才记录。没有实质变化时保持原文，不为每轮建立总结或同步所有入口。原生摘要用于核查遗漏，不能直接覆盖当前决定；取得的内容按[事件记录合同](../02_TECH/CONTEXT_CAPTURE.md)留存来源及可核实覆盖范围，取得不了的正文或范围保持缺口。模型整理的接续记录与工具原生摘要保持不同身份。

完整可复制的 [Codex 全局 AGENTS.md 参考稿](templates/GLOBAL_AGENTS_TEMPLATE.md)包含通用工作规则及文档治理章节。采用时将需要的规则合并到实际生效的 Codex 全局文件，默认位置为 `~/.codex/AGENTS.md`；自定义 `CODEX_HOME` 或存在 `AGENTS.override.md` 时先核对实际来源。沟通、浏览器和 CLI 等偏好可按使用者环境调整；它是工具包提供的参考，不是本仓库第二份生效规则，也不会由安装器自动覆盖使用者全局配置。全局只保留跨项目行为，项目级规则说明实际入口、职责与工具能力。已有规则应局部合并，沿用原路径和有效约束。

项目内共享正文归 `AGENTS.md`，`CLAUDE.md` 用 `@AGENTS.md` 引用。全局引用应指向使用者实际维护的共享文件，并核对启动方式确实读取；不假定所有客户端接受相同路径或加载方式，也不因文件已更新就认为运行中的执行者已采用。首次接入会提供等价的项目工作纪律；映射已有 rules 时由接入者在原来源合并，已有部署按升级指南局部采用。

验收看独立接手者是否能保留最新纠偏、未决项和必要原因，发现缺口并避免重复操作；规则、事件和回执齐全不代替行为验证。此约定不启动文档清理、全局配置同步或新的后台任务。

## 最小维护

每轮实质工作结束，AI 更新发生变化的权威来源，并给出一句结果、验证依据与未覆盖事项。小改动不强制新增 PRD、决策日志和长篇会话总结。一个字段只维护一处。

用户主动要求换会话前更新治理时，按[任务上下文合同](../02_TECH/TASK_CONTEXT.md)核对尚未保存的决定、纠偏、证据、必要操作知识和未完成现场。以缺失后是否导致重问、重复试错、错环境或重复执行判断必要性；区分记录已写、内容已核对和接续实测。沿原职责更新，交接只保留指针，不创建每会话一套文档，不启动清理或定时提醒。

待办保存任务状态、下一动作和专题引用，不再复制同一需求的限制、范围与待定清单。本次必须触及的旧条目若重复这些内容，先确认专题完整保留其依据，再把该处重复改为引用；不由此启动其他条目或历史的清理。

关键验证记录至少包含：目标、代码 revision（无 Git 时记录具体文件及 hash）、检查命令或观察方式、结果、原始证据、未覆盖范围。对未提交改动，注明 dirty 状态和可重现 diff / 文件 hash，不把结果归给一个不包含改动的提交。

## 接入、协作与验证

- [接入指南](../03_DELIVERY/DELIVERY_PROJECT_INSTANTIATION_GUIDE_v1.md)：源工具包与目标项目的边界、已有文档映射、升级。
- [Harness 合同](../02_TECH/HARNESS_CONTRACT.md)：派工、交付、验收和恢复。
- [任务上下文](../02_TECH/TASK_CONTEXT.md)：跨 AI 或压缩后的依据保持、分身份检查点和纠偏接回；必要记录不启动文档清理。
- [治理试验](../03_DELIVERY/GOVERNANCE_TRIAL.md)：让 AI 自己演练，用结果证明是否可接续。

自动检查能发现结构与声明之间的部分矛盾，不能证明文档里每句话都真实。没有进行的行为试验要显示“未验证”。
