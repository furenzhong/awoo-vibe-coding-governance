# v1.5 会话记录验证

日期：2026-09-28。本记录覆盖可选捕获组件及采用流程，不把以往版本的验证当成本版原生能力证明。私有原生会话、输入输出、事件与脚本摘要保留在维护者的隔离验证材料中，不随公开工具包发布。

## 实现及机器验证

Windows / Python 3.14：`python -X utf8 -B -m unittest discover -s tests -v` **104 项通过**，181.834 秒。包括既有 81 项、新核心 16 项和适配/采用 7 项。源仓库结构检查通过，153 个本地 Markdown 链接无缺失，`git diff --check` 通过。跨平台结果以本次提交的 CI 为准，不能借用 v1.4 的 CI。

核心验证：讨论不生成任务；执行绑定要求实际任务；显式替代绑定保留旧流；有真实 ID 的重试幂等；相同正文的不同事件保留；来源连续缺口及 unresolved 不被越过；无来源连续证据时水位置空；`no_change` 必须有理由和来源且不能隐藏最近原始输入；过期来源和缺失写入证据拒绝；迟到摘要不改现行文档；凭据过滤与元数据模式；持久化前失败、持久化后回执丢失的重放；恢复早于压缩落盘；路径与链接隔离。

适配/采用验证：准备计划不改目标；合并保留已有 hook 和权限配置；日志可回退本层；停用不捕获；正文策略变化不沿用旧绑定；嵌套 Git 工作区不归给父项目；输出路径 `..` 不绕过目标外要求；配置不冒充观察；检查不改目标。既有升级测试继续覆盖写入中断、部分成功和后来改动保护。

机器测试不证明模型每次判断正确，也不证明真实断电或任意外部写入者并发安全。

## 独立恢复及局限

合成项目保留旧摘要与最新决定：旧摘要宣称个别修改免费且共用通用模板；当前决定取消旧编辑入口、修改生成新版本、费用待定，只允许共享底层能力。真实 Claude 恢复正确拒绝旧承诺，保留费用待定，未把旧检查点的未知执行状态当作重做授权。它读到的是隔离合成资料，不是生产业务。

针对 C17，故意保存形式有效、含义错误的 `no_change`。原生 Claude 试验表达了正确判断原则，但其本地 `resume` 命令遭权限拒绝，没有读到该合成输入与回执；**不能据这次原生输出宣称 C17 完整通过**。

随后由未继承对话、未参与材料构造的独立 Agent 从正常入口实际执行本地 status/resume，读取原输入、错误回执与现行来源。它发现 16 条记录中唯一标为已核对的条目恰好含错误判断，指出 hash 有效不使旧承诺生效，保留价格待定、未知执行状态和压缩缺口。**本地工具加独立 AI 的 C17 恢复用例通过；原生 Claude 自动处理该缺口仍未验证。** 独立审查只读，没有把审查结论伪装成已送达原执行器。

## 真实目标采用

已在一个有成熟自定义治理和未提交业务工作的私有目标应用 13 个治理路径，实测收尾另有可逆的三文件记录层。应用前重取现场，保留其他任务同期变更；计划外 712 份文件逐字节一致，Git HEAD 保持。目标机器检查通过，仅保留既有规则入口长度提示。旧版采用材料保持，主层与收尾层均留目标外日志和私有便携恢复副本。

目标内新建的单次 Claude 验证会话仅确认捕获提示，不读取或执行业务。SessionStart/UserPromptSubmit/Stop 均 success，三条事件实际留存并按验证内容核对。桌面 Codex 的只读 hooks/list 在实际目标发现五条配置，均 enabled=true / untrusted，无错误；尚未运行 Codex hooks，须按宿主原生流程信任。没有重启旧业务会话，不能推定它们已重载配置。
