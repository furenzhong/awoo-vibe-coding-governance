# 会话上下文自动记录与恢复的实施方案

方案版本：1，实施注记更新于 2026-09-28。最初按用户要求仅保存方案；后续用户明确要求“落到项目里面吧”，已进入工具包实现和目标项目采用。本文保留设计及验收依据，不把未测能力写成已完成；实际接口见[操作指南](../02_TECH/CONTEXT_CAPTURE.md)，实施进展只在[当前状态](../00_PROJECT_CONTROL/PROJECT_CURRENT_STATUS.md)维护。v1.4.0 不包含此功能。

首版实施选择：摘要正文与元数据原子写入同一个 event JSON，不另建 `summaries/*.txt`；覆盖在查询时从不可变事件和回执派生，不持久化 `coverage.json`，避免双文件半成功。语义候选由已有写入者及 upgrade 机制安全应用，`reconcile` 校验实际来源和结果，不另造业务文件事务。下面的目录示意表示职责，实际目录以操作指南为准。原生事件须按本机宿主能力逐项采用，不支持完整 hooks 的旧工具保留模型协助通路。

## 1. 要解决的问题

现有[任务上下文合同](../02_TECH/TASK_CONTEXT.md)已经规定派工快照、分身份检查点、纠偏及恢复核对，但仍依赖模型自行判断何时记录。检查器能够检查已经存在的记录，不能发现“聊天出现了重要纠偏，却没有进入任何记录”。

另一类失败是原生摘要曾经准确，但后续决定已经改变。把它完整保存、格式校验通过或在文件顶部写“最新”，均不能证明接手正确。目标是同时做到：

1. 工具提供的可读原生摘要能够留存，并保留来源、范围及历史身份。
2. 影响下一步的用户约束、取舍、未决项和实际现场进入已有治理来源。
3. 可以指出哪些可观察消息尚未核对，以及哪些范围根本不可见。
4. 换模型、换会话或压缩后，先识别旧依据与未处理变化，再继续相关动作。

**分工：模型提取含义，运行层保存真实事件和暴露缺口，恢复过程检验理解。** 任一部分都不能独自证明“上下文无损”。这里不保存内部思考过程，也不要求把全量聊天变成每轮必读文档。

## 2. 必须保持的边界

- `rules/status/handoff/decisions` 四个全局来源不变；专题保有业务权威，不新增全局 `MEMORY.md` 或第二份当前事实。
- 原生摘要是历史线索。用户粘贴旧摘要作为背景，不自动恢复其中已被否决的要求。适用性由来源、授权和明确替代关系决定，不能仅按时间较新裁决。
- 已确认要求、模型提案、观察结果、未决问题分别记录。没有执行证据不能写完成，未知在途操作不能写成已停止。
- 自动保存工作记录与自动清理文档分开。任何会话事件均不启动 inventory、全库归类、合并压缩、归档、删除或“要不要清理”的询问。
- 新能力按项目明确采用，部署时核对当前工具和生效范围；不能因上游更新而自动接管所有项目或会话。既有授权内的正常记录不增加逐条审批。
- 不把实施成本转交用户：AI 识别现有职责、准备适配和检查；只对证据无法裁定且影响下一步的意图冲突提出具体问题。
- 新机制从真实可查的时点开始，不补造过去事件、会话采用历史、漏失消息或业务任务。

## 3. 首版范围与工具能力

首版包括工具中性的事件记录、摘要留存、增量核对和恢复检查，以及 Claude Code、Codex 的独立适配。支持 DeepSeek 的具体 harness 必须先确定程序及版本；模型名称不能替代运行层接口。

以下为 2026-09-28 实际读取官方文档所得，不代表本机已启用或实测。接入时重新核对版本和能力，保存一个真实事件样例及结果。

| 适配对象 | 文档确认的能力 | 设计约束与本机验证要求 |
|---|---|---|
| Claude Code | `PreCompact`、`PostCompact`；后者提供 `compact_summary`；`SessionStart` 可区分 `compact`；会话日志可能异步滞后 | 优先接收事件提供的摘要；压缩后留档与恢复注入分别测试。不能假定日志已含最新消息，不能假定 PostCompact 能改变压缩结果 |
| Codex | `PreCompact`、`PostCompact` 支持 manual/auto；`SessionStart(source=compact)` 在压缩后下一模型请求前提供上下文 | 文档未承诺 PostCompact 提供可读摘要正文。先验证事件和恢复指针；有稳定可用摘要接口才启用正文捕获，不依赖私有日志解析作为首版核心 |
| 自控 harness | 若拥有消息入口、执行结果及压缩调用，可在这些边界接入 | 必须实测顺序、恢复与失败行为；不因使用某模型便声称具备这些控制 |
| 无可用事件接口的工具 | 可能只能由模型维护检查点或读取最后可见材料 | 明确降级为模型协助记录，覆盖范围可能未知；不声称自动完整捕获 |

OpenAI Responses API 的部分压缩产物是不可读的加密项，不等同 Markdown 摘要；只保存支持恢复所需的可用定位和状态，不虚构正文。第三方摘要也不自动取得指令优先级。

适配能力逐项登记 `supported / unsupported / unverified`，至少包含事件可见性、可读摘要、来源顺序/定位、恢复注入、实际目录/会话定位。文档存在不等于 installed；配置存在不等于 enabled；enabled 不等于已经发生真实捕获。工具要求的信任流程按其实际机制完成，不能绕过或伪造。

事件可见性还须按 kind 分别登记：用户输入、压缩前、压缩后、结果和恢复分别留实测证据。只验证了 PostCompact，不能声称已覆盖“纠偏后尚未压缩就换会话”的场景；缺用户输入通路的适配器必须在该项报告降级。

首版不做通用后台编排器、所有工具日志逆向解析、定时全库扫描、自动聊天全文入库、自动迁移旧任务或跨工具隐藏状态复制。

## 4. 记录归属与最小目录

执行任务继续复用 `<tasks_dir>/<task-id>.json` 及对应子目录，沿用现有上下文、检查点和纠偏字段。每个活跃身份维护自己的检查点，任务生命周期仍只在任务 JSON 中维护。

讨论没有获准实施时，确认内容回到已有专题，续接线索由交接入口引用。讨论会话通过下面的私有绑定记录关联专题，**不为满足现有执行 schema 伪造 `running`、Git 基线、执行者或验收命令**。以后开始真实执行时再建立或关联实际任务，不倒填派工时间。

拟议私有目录如下。部署者可按项目私有存储约定映射；默认排除 Git，不进入公开工具包。这里只留来源与过程证据，不成为业务事实来源。

```text
.project-os-local/context/
  bindings/<binding-id>.json
  sessions/<stream-id>/events/<capture-id>.json
  sessions/<stream-id>/summaries/<capture-id>.txt
  sessions/<stream-id>/reconciliations/<reconciliation-id>.json
  sessions/<stream-id>/coverage.json
  capabilities/<adapter-id>.json
```

运行层写此目录；模型通过受控的“提交增量”入口提出语义内容，不直接改事件编号和捕获回执。`coverage.json` 是可重建的派生索引，不是第二份项目状态。目标内共享文档仍由原职责的写入者维护；捕获 hook 不直接修改业务合同。

跨工作区派工时，仅携带相关快照、可共享来源摘录及版本，不复制完整私有存储。必要引用若只能在原机器访问，应随派工提供最小材料，不能交付一个接收方无法打开的绝对路径。

## 5. 数据合同：把四种事实分开

下表定义首版必需语义，具体 JSON schema 在实施阶段建立；字段不能混入现有根任务目录而被 v1.4 的任务扫描误认。

| 记录 | 由谁写 | 最小字段与含义 |
|---|---|---|
| 会话绑定 | 运行层，AI 核实归属 | `binding_id`、项目身份、实际工作区、adapter 及版本、原生 `session_id`（不可取得则 null）、`mode=discussion/execution`、`topic_refs`、可选 `task_id`、启用时点与能力证据。不得用目录名猜绑定或用最近会话猜执行者 |
| 捕获事件 | 运行层 | `capture_id`、`stream_id`、`kind`、接收时间、原生事件/turn 定位（可空）、可用来源游标、内容定位及摘要、顺序可靠性、可见范围。区分用户输入、压缩前/后、派工、结果、交接与恢复 |
| 原生摘要记录 | 运行层 | 所属捕获事件、原文位置与字节摘要、原生覆盖范围（未知则 null）、是否脱敏/截断/正文不可取得。来源不变，不能后写成“已经确认的需求” |
| 语义核对回执 | 模型提出，运行层落盘 | `reconciliation_id`、本次实际读取的事件列表/区间、来源版本、`changed/no_change/unresolved` 分类、增量引用、受影响动作、写入结果/依据、待处理原因。no_change 也是判断，不能仅凭该字样验收业务 |
| 覆盖索引 | 运行层派生 | 绑定、已观察范围、已持久捕获位置、已核对连续位置、缺口列表、未知范围、依赖的核对回执。不标“语义正确率” |

语义增量至少区分：有效约束、替代/撤销关系、假设、未决项、已观察动作及证据、下一步。每项带来源引用；只保留会改变后续选择的内容。专题正文使用定位引用，不复制到所有入口。

三个编号独立：`capture_id` 定位事件，`checkpoint_revision` 定位某身份的恢复记录，现有 `context.current_revision` 定位实际派工要求。**发生压缩不改变派工要求，不应单凭压缩就递增 context 版本或伪造纠偏。** 真正改变要求时按现有 TASK_CONTEXT 生成新快照及纠偏，保留送达/采用证据。

覆盖计算规则：

1. 按每个会话来源流分别计算；不存在未经证明的跨会话总顺序。负责人核对了自己的消息，不能顺带声明 Claude 的尾部已覆盖。
2. 运行层接收序号只代表接收到事件的次序。只有适配器确实提供稳定来源游标及连续性依据，才声明该可见范围连续；乱序、日志未刷盘和未观察区间必须显式留下。
3. 捕获、模型核对、写回对应来源、执行者采用分别记录。保存了摘要不推进核对位置；模型说“已更新”但没有可核实写入结果，也不能结清需要写回的事件。
4. `reconciled_through` 只越过已经处理的连续区间；中间遗漏不能被较新的回执掩盖。无需写文档的事件可以由 no_change 回执结清，但仍不证明没有语义误判。
5. 用户意图暂不能裁定时保存冲突和原始依据。记录可以已落盘，相关动作仍待澄清；不能把“冲突记录好了”当成“冲突解决了”。
6. 无来源游标时，只列明确处理过的 capture ID，连续位置置空并说明未知。时间戳较新、文件存在、hash 正确都不构成全量覆盖证据。

例如实际可见事件为 40、41、42，只有 40 和 42 获核对，连续位置仍停在 40，41 留作缺口。该例仅示范计算，不假定工具本身使用数字消息 ID。

`no_change` 回执必须包含简短判断依据及实际读取的来源引用，不接受只有一个布尔值的自证。恢复时它不能屏蔽后续用户原话或权威来源的版本变化；涉及当前动作的最近输入仍可按需复核。覆盖索引只回答处理范围，不能充当过滤纠偏的语义权威。

## 6. 启用、触发与执行流程

### 6.1 一次性项目采用

实施获得授权后，先识别实际项目与会话、既有任务/专题、权威来源和写入归属，再选择所需适配器。通过隔离事件验证后，登记实际启用范围。没有 binding 时可以保留事件为未关联材料，但不能猜测业务归属并更新任意项目。

新讨论可以由 AI 依据明确主题关联已有专题；无需给所有随口问答新建文件。纯问答没有需要跨会话保留的决定或现场时，继续原交互。实际出现跨会话实现、委派或可恢复操作时，才进入执行任务通路。

### 6.2 触发表

| 可观察时机 | 运行层动作 | 模型动作与写入门槛 |
|---|---|---|
| 收到用户输入 | 在已采用会话内保存真实来源定位及必要输入证据，标记待核对 | 同轮结合工作判断 changed/no_change/unresolved；不另调用模型生成整轮长摘要 |
| 用户纠偏改变下一步 | 保留纠偏来源；派工/相关写入前检查是否已处理 | 先保存具体变化和适用范围，再进行依赖它的动作；材料足以裁定时不向用户重复确认 |
| 形成关键结果或阶段交付 | 留存真实结果/操作定位，不复制大段无关工具输出 | 更新自己的检查点，区分完成、测试和验收；简单命令无新事实时不创建快照 |
| `PreCompact` | 持久保存已有待写记录、可观察位置和未完成操作定位 | 不假定此时模型还有一次写文件机会；缺内容留下缺口，不默认阻止压缩或启动额外模型调用 |
| `PostCompact` | 有正文则留存原生摘要，没有则保存事件及不可取得原因 | 不把原生摘要直接升级为当前要求；安排下一次可用恢复核对 |
| 恢复/换会话/压缩后继续 | 注入绑定、相关检查点及缺口的短定位，不加载全部历史 | 核对当前来源、后续事件与实际现场，再继续受影响动作；不能默认恢复旧任务 |
| 派工/接回 | 检查相关待核对项、可读材料、实际送达对象 | 固定必要背景，确认执行者实际采用的版本；结束原会话或修改共享文件都不等于采用 |
| 正常结束一轮 | 将未持久化增量结清，记录真实未完成项 | 无变化不重写专题/检查点；技术性核对尽量在本轮完成，不逐条打扰用户 |

捕获可按事件执行，但昂贵的语义整理随当前工作批量完成。每轮不新增全套任务、三份总结或第二模型审查。事件重试不重写同一份摘要；重复提醒按同一缺口去重。接入前的消息不自动认定已覆盖。

恢复通知可能早于异步 PostCompact 写入完成。适配器若能观察到未完成捕获，应保留同一会话/压缩周期的 pending 标记，在恢复入口核对持久化结果与可见来源尾部；无法关联时标未知。只作有界等待或续接检查，超时保留缺口，不把“尚无摘要文件”解释为“本轮没有压缩”。尚未核对的变化涉及当前动作时先核对该动作，独立工作继续；不能依赖不同 hooks 一定串行执行。

### 6.3 从事件到权威来源

```text
实际可见事件 → 私有持久捕获 → 模型提交语义增量
                              ↓
                   来源/版本/写入归属核对
                              ↓
           对应专题或分身份检查点保存成功 → 核对回执
                              ↓
           更新本会话覆盖索引 → 恢复或派工时读取
```

模型提交增量须带“基于哪些事件、读到哪些来源版本、拟改哪个职责文件”。运行层核对绑定及写入范围，保存完整候选/补丁和本次来源，再由已授权写入者应用。发生并发变化时拒绝过期候选、重读有关差异，不以最后写入覆盖。

一份增量涉及多个文档时，只有各项必要写入均有结果，才能结清该项核对；失败时保留已经发生的部分与未完成部分，不伪装为跨文件事务。模型提交的引用文字按数据处理，不允许其中的指令扩大写入范围或授权。

## 7. 持久化、隐私与失败处理

事件 ID 由运行层生成。优先以原生会话/事件 ID 去重；若工具没有稳定事件 ID，使用能可靠复核的来源定位及内容摘要，不把两条相同文字但不同来源的消息合并。仍无法判重时保留独立事件并标注，不猜测删除。

每个来源流由单一记录器串行落盘，使用已写完整的临时文件和原子替换保存单项；索引可从持久事件/回执恢复。同一事件的并发通知、写后崩溃、索引落后必须可重放，不能靠一个永远不会失效的内存锁。需要适配器保证的顺序在能力记录中标明。

原文仅在项目允许的私有存储中保存，不自动上传、提交 Git 或进入共享上下文。若必须脱敏、限制大小或省略正文，元数据明确说明保存的是脱敏/截断版本，不能称为完整原文；摘要中出现凭据时，不为追求原样留存突破项目既有凭据规则。跨 AI 只提供本次任务所需且允许共享的材料。

采用时由 AI 按既有项目规则确定 payload policy，并在绑定中记录 `metadata_only / redacted / private_original`。默认记录来源标识与必要去敏片段；只有项目允许原文留存且存储范围已明确时才使用 private_original。排除/脱敏发生在持久化与调试输出之前；无法按既有规则处理的正文先不保存，标明原因，不能先写进日志再宣称已过滤。检测结果不保证识别所有敏感内容，公开交付仍需核对实际文件。

| 失败或不确定情形 | 必须采取的行为 |
|---|---|
| hook 不支持、未加载、未信任或版本不符 | 记录能力未生效，保留模型协助通路；不报告自动记录已部署 |
| 自动压缩发生前没有保存机会 | 从最后持久检查点恢复，核对可见尾部；缺失区间如实保留，不编补事件 |
| 日志滞后、消息乱序或正文不可读 | 标记未知/待捕获，不把接收时间当源顺序；只在实际可读取边界补核 |
| hook 超时、磁盘写入失败、大小限额 | 不确认保存成功、不推进覆盖位置；保留已有材料并记录可见故障，不自动删除旧材料腾空间 |
| hook 返回后进程中断 | 依据已落盘事件/候选/回执重建状态；未确认的外部操作先查原 ID，不重新发起 |
| 模型漏提约束或错误分类 no_change | 结构检查不能自动识别全部问题；通过恢复案例和关键选择发现，保存纠偏及受影响范围 |
| 旧会话迟到写入 | 保留原事件，不覆盖新检查点或新决定；比较已读来源版本，重新核对后才允许写回 |
| 找到旧摘要与当前来源冲突 | 查明确替代关系与原始依据；无法裁定只暂停依赖该冲突的动作，其余工作继续 |
| 接手者看不到私有原文 | 提供允许共享的必要摘录/快照或保留缺口，不把不可访问的链接当作已交付 |

正常成功静默保存。短暂技术故障优先由 AI 在现有授权内处理；未解决且影响接续时才告知用户具体缺口。停止/恢复 hook 的重入保护必须有界，不通过无限“请再总结一次”阻止结束，不用后台定时催问。退出自动记录时只停新的捕获，保留已有恢复材料；后续清理仍需用户主动要求。

## 8. 与现有协议兼容及拟改动范围

| 对象 | 实施时的最小改动 |
|---|---|
| `TASK_CONTEXT.md` | 增加事件引用、覆盖边界、原生摘要地位及恢复顺序；沿用派工/纠偏合同，不让压缩产生虚假新要求 |
| `HARNESS_CONTRACT.md` | 补会话绑定和派工前核对；保持任务生命周期唯一，讨论通路不强塞执行 schema |
| 工具中性记录组件 | 建立 capture、reconcile、status、resume 的可测试内部接口，负责单项落盘、索引、幂等和缺口报告；名称为设计意图，不是已有 CLI |
| 工具适配器 | 各自解析已验证事件、映射目录/身份和能力，输出同一内部格式；项目级配置显式采用，失败可停用单个适配器 |
| `project_os.py` 的 check/snapshot | 增加可选覆盖报告；区分 not_configured、configured_unverified、observed，并分别列缺口与未知。旧项目无配置继续兼容，不据文件存在判已采用 |
| 示例和试验 | 只放合成事件、脱敏协议形状、重复/乱序/缺口/旧摘要案例，不含真实私有会话和业务原文 |
| 接入指南、双语 README | 仅在实现及实际验证后说明可用能力、安装条件、覆盖边界与停用方式；保持清理主动唤醒规则 |

若需增加配置，只增加可选的适配及存储设置，`sources` 仍只有四项。既有 JSON 的新字段采用明确版本/可选扩展，旧任务不强制迁移。不能只把 kit_version 提高就宣称所有会话均已覆盖。

捕获/恢复工具不负责批准需求或强制停止外部执行器；实际纠偏送达与采用继续按 TASK_CONTEXT 留证。纯模型通路、只有事件的通路、可读摘要的通路分别报告证据，不能用一项成功代替全部适配器通过。

## 9. 实施顺序与交付门槛

| 阶段 | 工作及产物 | 进入下一阶段的依据 |
|---|---|---|
| A：锁定合同 | 固定字段、归属、触发与失败语义；准备合成原始事件和预期结果 | 能独立判断纯讨论、执行、旧摘要、已替代决定和未知范围；不改生产项目 |
| B：记录组件 | 在隔离目录实现捕获、核对回执、覆盖索引及重放 | 重复、乱序、部分写入、恢复和过期候选用例通过；无模型/API 依赖 |
| C：Claude Code 适配 | 核实实际版本，接入摘要事件与恢复入口；手动压缩先验证通路，再做自动压缩验证 | 留下真实会话/事件及文件结果，恢复能看到新纠偏；手动成功不替代自动成功 |
| D：Codex 适配 | 分别验证前后事件和压缩后的恢复注入；正文能力按实际接口决定 | 即使取不到原生正文，也能如实显示事件、检查点和缺口；未验证能力仍标未验证 |
| E：真实接力 | 在获准范围内选择下一项小任务，运行负责人→执行者→负责人接回；讨论单独做续接案例 | 依据明确来源作出正确关键选择，未重复在途操作，用户不需要重述完整历史 |
| F：发布与采用 | 更新合同、双语说明、相称回归、实际适配矩阵及版本化证据；对目标生成局部采用/恢复记录 | 发布内容与验证范围一致，私有内容不外泄；明确哪些工具已采用、哪些待接入 |

优先完成一条实际可用的接力，再扩展更多 harness。每阶段保留未通过项，不能把设计文档、模拟 hook 或手工填写的 JSON 当真实运行证明。停用时撤去本次明确配置/注入，保护原有其他 hooks 和任务记录，不整份覆盖配置文件。

## 10. 验收案例

以下为公开合成案例，复用真实问题的结构，不包含业务原文、私有路径、会话 ID 或样片资产。预期结果须在独立接手试验前固定，接手者只接触正常入口。

| 编号 | 输入或故障 | 必须观察到的结果 |
|---|---|---|
| C01 旧摘要不能翻案 | 旧摘要称某编辑免费；后续决定取消该编辑入口、修改走新版本，费用待定 | 恢复者保留这三个事实；既不恢复免费承诺，也不推定一律收费；能指出替代来源 |
| C02 保留创作约束 | 旧笔记推荐通用模板，当前决定只允许共享底层绘图能力 | 下一关键选择不恢复模板化镜头；解释来自当前决定而非摘要标题 |
| C03 不等压缩 | 一条重要纠偏后立即换会话，没有发生压缩 | 新会话可从已保存来源或明确缺口发现这条变化；不能宣称无变化并按旧要求继续 |
| C04 漏记可见 | 连续可见事件中间一项未核对，但后一项已保存 | 连续位置不越过缺口，报告具体来源；修复后保留处理证据 |
| C05 多会话范围 | 负责人记录最新，执行者尾部不可见 | 分别显示范围，不声明项目上下文已全部同步 |
| C06 讨论不变执行 | 只有方案探索，部署与费用尚未确认 | 不创建虚假 running 任务、不新增付费调用、不把提案升级为实施授权 |
| C07 低维护负担 | 连续若干次无决定/现场变化的问答，随后一次关键纠偏 | 无变化只需轻量处理标记，不增加语义快照；纠偏落到唯一来源，不广播多个入口 |
| C08 真实压缩 | 用无敏感内容的合成会话在已支持工具中实际触发自动压缩 | 保存真实事件；允许原文保存的适配器核对原文字节，脱敏模式核对处理关系，缺正文者如实声明；恢复时读取当前来源 |
| C09 重复与乱序 | 重复通知、异步尾部延迟、先收到后面的事件 | 有稳定标识者幂等；无法判断者保留未知，不吞消息或伪造连续性 |
| C10 部分失败 | 摘要写成功但索引失败，或语义候选写入一半后中断 | 重放能识别已有内容和缺口；不把部分成功写成已结清，不损坏旧检查点 |
| C11 旧写入者返回 | 旧会话按过时来源提交新摘要或文档候选 | 留历史证据并拒绝覆盖新决定，保留可复用成果；按实际影响核对 |
| C12 在途操作 | 旧检查点显示执行中，当前真实状态未知 | 先定位原会话/操作，不重复派工、生成或扣费，不伪造 stopped/adopted |
| C13 清理边界 | 压缩、交接、记录较多、恢复发现冲突 | 均不调用 inventory、不归档删除、不询问是否清理 |
| C14 能力降级 | hook 不存在、未生效、不可读摘要或日志缺尾部 | 明确显示实际能力与未知范围；不以另一工具通过作为该工具通过 |
| C15 保存与共享 | 原摘要含不应提交的信息，接手者位于另一工作区 | 私有材料不进 Git/发布包；脱敏身份明确，接收方实际能读所需依据 |
| C16 停用恢复 | 去掉本次适配配置后继续普通开发 | 不影响原任务/规则/其他 hook；已有记录保留，报告从何时不再捕获 |
| C17 故意错误分类 | 把一条影响当前动作的用户纠偏误分类为 no_change，且覆盖索引看似最新 | 独立恢复者仍核对相关原始输入与当前来源，发现错误并形成纠偏；不能因水位最新直接通过 |
| C18 恢复早于落盘 | 恢复通知先到，压缩摘要仍在异步写入 | 识别 pending/未知并有界核对；晚到摘要正常接入，既不丢失也不重复，不无期限阻止结束 |

机器测试验证结构、顺序、落盘与故障行为；独立接手验证含义；真实工具试验验证事件和接力。三者分别留证。合理的交付报告是“哪些会话、到哪些事件、哪些约束与动作核验过、还缺什么”，不报告无法证明的无损率或模型记忆完整率。

## 11. 官方依据与重核点

已读取的来源：

- [Codex Hooks](https://learn.chatgpt.com/docs/hooks)：PreCompact/PostCompact、SessionStart compact、事件字段、hook 信任及 transcript 格式边界。
- [Codex App-server](https://learn.chatgpt.com/docs/app-server)：contextCompaction 事件可观察压缩发生，不能据此假定获得摘要正文。
- [Claude Code Hooks](https://code.claude.com/docs/en/hooks)：PostCompact 的 compact_summary、日志异步滞后及恢复事件。
- [OpenAI Responses Compaction](https://developers.openai.com/api/docs/guides/compaction)：部分压缩项为不可读加密数据，不能当可共享文本摘要。

实施前只需补齐具体工具版本、真实事件负载、绑定/存储位置和各适配器覆盖能力，这些由 AI 调查验证。只有实际无法确定用户意图、项目归属或允许共享范围时才提问。本文不预设工具自动压缩一定可以被拦截，也不以无限拦截来换取表面完整记录。
