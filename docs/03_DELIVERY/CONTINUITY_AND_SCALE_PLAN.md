# 交接可执行性与记录增长补强方案

日期：2026-09-30。用户已同意实施：明确换会话前交接、补足操作接续信息、测量并改善历史增长开销；源工具包验证后，按现有升级流程局部采用到已有项目。候选版本为 1.6.0；实施或本地采用不等于正式发行。

## 要解决的问题及假说

现有规则支持跨会话、分身份检查点和新会话盲接，但操作入口、已成功步骤与临时现场仍可能只留在聊天或工具输出中。可选事件适配器并非完整工具日志。另一方面，事件与回执持续新增，当前捕获和恢复路径存在全量与重复读取。

假说：按“缺失后是否导致重问用户、重复试错、错环境或重复外部操作”保存必要操作知识，并复用已有职责文件，可以改善可执行交接；减少同一次查询的重复读取及低效查找可以降低历史增长开销。收益分别通过无历史接手和分规模基准验证，不以文档齐全或文件数减少证明。

## 本轮范围

1. 用户明确说准备换会话／更新交接时，检查尚未落盘的决定、纠偏、证据、操作依赖和未完成现场。沿用现有正常事实维护，不新增每轮总结、定时提醒或退出拦截。
2. 稳定操作知识更新已有部署／操作说明；临时现场进入既有任务或身份检查点；handoff 保留指针。字段按实际适用性填写，不要求每个项目创建服务器清单。密码／令牌仅留获取位置，不保存值；访问曾成功不等于当前登录态仍可用。
3. 在现有恢复合同中区分：记录已保存、接手所需内容已核对、实际接续已验证。缺失信息应明确列出；不声称任意会话无损恢复。
4. 以合成的单流和多会话历史测 capture/reconcile/status/resume 的耗时、JSON 读取次数和读取字节，比较固定基线与候选。先复用单次查询中的解析结果、集合和文件摘要；保留写入前后用于变化检测的复核。只有基准支持必要性时引入持久索引；索引必须可重建，旧 JSON 不迁移也可读取，落盘中断不得隐藏原始事件或制造完整水位。
5. 同步新安装规则、合同、模板、操作例子、双语 README 与升级说明。历史记录格式及四项权威映射保持兼容。旧任务不补表，既有历史不改写。

## 不变的边界

- 盘点、归类、合并、归档和删除仍仅由用户明确请求启动；交接、事件增长和升级均不启动或提示清理。
- 不抓取全部聊天或全部工具输出，不增加后台模型调用；本轮不声称实现全量记忆、自动登录态迁移或语义完整性认证。
- 优化访问成本不等于限制存储增长；原始事件和回执保持保留。未知、pending、unresolved、过期来源及截断提示不能为提速被吞掉。
- 只在源工具包及隔离试验里开发。实际目标按明确候选、写前变化检查和目标外日志应用；保持业务文件、凭据、未提交工作、既有决定与运行进程。
- 记录更新不证明运行中的其他 AI 已采用；无法确认的执行状态继续标未知，不重启或重派原业务任务。

## 实施与归属

| 工作流 | 写入范围 | 交付 |
|---|---|---|
| 记录性能 | `scripts/project_os_context.py`、相关测试、专用基准脚本 | 兼容优化、对照数据、故障与语义回归 |
| 交接合同 | 技术合同、交接模板、试用规则、公开合成例子、双语 README | 按需操作接续要求与可执行示例 |
| 集成与采用 | 本方案、规则入口、安装器、版本/目录/决定/验证记录、目标升级候选 | 新安装覆盖、独立接手证据、局部采用和恢复日志 |

在独立工作流开始前锁定各自写入范围；主维护者检查实际差异和结果。新事实或纠偏写回本方案或对应证据，不靠聊天独存。

## 验收条件

| 编号 | 实验 | 通过条件 |
|---|---|---|
| S01 | 无历史接手：测试环境有已验证操作方式、旧误导材料、未结束操作 | 仅从正常入口找到正确环境和步骤，先查询已有操作，在隔离环境实际完成一个下一步，不触及生产或外部服务 |
| S02 | 必要访问定位或关键步骤缺失 | 具体指出缺口，只暂停依赖动作，不编造凭据／地址／成功，不重发未知操作 |
| S03 | 用户请求换会话前更新治理 | 已变化内容进入原职责文件，handoff 指向来源；无重复进度、无自动清理、无强制每会话新文档 |
| S04 | 不同规模及多会话基准 | 报告规模、环境、实测耗时和读取量；比较相同内容的结果一致性，说明仍然线性增长的路径及未测范围 |
| S05 | 错误 no_change、过期来源、乱序、迟到摘要、重复事件及写中变化 | 保持既有缺口和拒绝行为，原有回归加必要新回归通过；不能删掉最终变化检测以换取速度 |
| S06 | 新安装及已有项目升级 | 新安装能发现接续规则；目标候选不覆盖业务事实，范围外文件核对、局部回退字节检查及采用记录完成 |

先封存盲接预期答案，再让未参与材料构造且没有本轮历史的 Agent 从正常入口执行；不能提供答案或通过条件。性能基准与接手试验分别报告，不用机器检查替代语义验收。

完成条件：上述适用案例有实际结果，相关回归和治理检查通过，目标局部采用与恢复依据可核对，剩余边界已明确。性能未达目标时修正受影响实现再测，不扩大成未经验证的长期存储重构。

## 实施结果入口

首次规模观察发现：5,000 事件单流捕获约 12.5 秒，超过当前生成的 hook 10 秒限时，仅优化查询不足以覆盖该问题。试验中的批量祖先检查虽更快，独立审查发现临时目录重定向可绕过检查，已撤回该做法。最终实现只复用路径对象，每条记录仍重新检查完整祖先链，检查文件类型／链接、打开前后身份与修改情况，完整解析 JSON，并在扫描结束复核目录；新增临时重定向并恢复原名的回归。

查询复用同次操作的解析结果和来源摘要，核对写入仍保留最终来源变化检查。原始记录不迁移、不删减，不建立持久索引。安全候选的大单流捕获仍可能超过 10 秒，本轮不登记为已解决；这一限制与查询收益分别报告。后续是否改变存储或捕获协议须依据实际超时证据另行设计，不能以清理历史代替修复。分规模结果及语义一致性见最终验证记录，不据单个样本承诺任意规模不超时。
