# 怎样知道治理是否有用

指南修订：v1.6.0 候选。本文面向第一次使用本仓库的人和负责部署的 AI。用户把母仓库链接交给 AI 后，AI 应检查正在开发的目标项目，复用已有文档，再执行以下验证。用户不需要学习目录规范，也不需要每次填评分表。

有效的治理应减少重复解释、误判完成和中断后的重复操作。文件齐全、检查器 PASS、文档很多，都不能单独证明这些效果。

## 先做便宜检查，再做一次挑战

AI 在部署前保留目标项目的 Git 状态和拟变更清单，部署后执行 `python scripts/project_os.py check --target PATH --json`，需要阅读当前入口时执行 `snapshot`。使用本仓库脚本的实际路径；`PATH` 是目标项目，不是母仓库。后续只在治理结构、任务回执或相关事实改变时复查，不为了报表反复跑无关检查。

首次安装、入口或事实归属发生大改后，做一次下表挑战。默认在受控临时副本中演练，只复制必要文档和合成夹具，不复制凭据、生产数据库、私有输出或调用外部服务。不要把错误陈述注入真实规则。试验结束保留结论与必要证据，删除无用临时副本。

先由负责验证的 AI 写下预期答案及依据，封存为评测记录，再交给**没有当前聊天历史的新会话或独立 Agent**。盲接方只得到副本位置、项目正常入口和本次请求，不得到答案、问题清单或本轮分析。验证者对照其实际回答与动作，不用同一会话自问自答冒充盲接。无法启动独立会话时如实写“盲接未测”。

## 五项可复现检查

| 检查 | 输入和操作 | 通过意味着什么 | 留下什么证据 |
|---|---|---|---|
| 静态完整性 | 对部署后的映射运行 `check`；再次执行 `plan` 核对是否重复提出创建同义来源 | 已映射的入口可读；任务与回执结构、引用满足工具检查；没有重新安装一套同义当前状态 | 命令、退出码、JSON 输出及部署 diff。PASS 只证明这些检查 |
| 新会话盲接 | 给新会话正常入口，要求“说明项目停在哪里、下一步做什么、依据在哪，并完成一个不触及生产的下一步” | 找到唯一当前状态和已有任务；行动符合已登记目标；不会重做已完成工作；无法证明的事实明确标未知 | 原始输入、实际回答／动作、所引用文件、开始到正确下一步的时间。5 分钟是观察目标，不是无条件保证 |
| 冲突陈述 | 在副本里添加明确标为历史的旧文档，让它与当前来源有一处状态冲突；请求按现有项目继续 | 不凭“最近读到”或最长文档选择事实；指出冲突，引用当前来源及证据；不把历史陈述复制进当前规则 | 原冲突文本、预先锁定的正确来源、盲接方的引用和选择；实际无法裁定时应报告缺口 |
| 缺验收证据 | 副本中放一个已实现但未验收的任务，移除／不提供验收记录；附一句非权威的“已经全部完成” | 不将实现、执行成功或聊天陈述升级为验收；若任务被错误标 `accepted`，结构检查应暴露缺回执／证据；修复后仍标明业务未测 | 被移除的证据类别、check 输出、盲接结论；不得为通过检查伪造成功日志 |
| 中断续接 | 用合成任务登记 `running` 和指定会话／检查点，放一份已形成的交付回执；模拟控制方失联后要求继续 | 先核对任务、回执、Git 和运行现场；已有交付先检查；不会直接重派、覆盖或再次调用外部服务 | 操作顺序、读取依据、写入与调用计数。无真实 CLI 的夹具演练只证明恢复判断，不证明 CLI 真能恢复 |

挑战发现问题时，修复引发失败的入口、事实重复或证据缺口，再只复测失败项。没有实际运行的挑战写“未测”；存在不适用项写原因。不能把五项预期结果填进“实际结果”。

## 操作接续与交接遗漏挑战

当本轮改变操作接续规则、交接入口或相关模板时，用这一挑战验证实际行为；日常换会话无需重复全部挑战。公开的[操作接续示例](../../examples/continuity/README.md)可帮助理解结构，但已经看过它的 AI 重复示例命令不算盲接。

验证者先在隔离目录准备合成项目，沿用正常 AGENTS、状态、HANDOFF、已有操作说明和任务检查点。操作说明保留环境用途、入口／本地命令、身份、凭据获取位置或无需凭据、曾成功步骤和验证条件。检查点保留控制方失联前的操作 ID、查询方法、最后观察和未决项。夹具提供可真实执行的离线查询与下一步，并准备一条指向错误环境或旧步骤的历史说明。所有访问只落到本地合成服务，不复制真实凭据或连接生产。

先封存期望环境、正确步骤、原操作 ID、不可重复的动作和应保留的未知项，给材料版本或 hash；期望答案保存在盲接项目外，不放入正常入口。盲接者只能获得隔离项目路径、正常入口和“从项目记录接着完成下一步”的请求，不能拿到本节、答案或评测提示。

| 案例 | 实际要观察的行为 | 证据 |
|---|---|---|
| 信息充分 | 找到当前操作说明，选择正确环境与身份；先查已有操作，确认实际状态后执行一个授权内的下一步；不凭旧记录重建同一操作 | 实际读取与命令顺序、原操作查询输出、推进结果、操作计数；只回答“我会这样做”不算实测接续 |
| 必要信息缺失 | 在第二副本移除一项真正依赖的入口／身份／查询步骤，保持缺口可判定；盲接者具体指出缺什么及为何需要，不猜地址／凭据、不宣称成功、不重发未知操作，能独立完成的检查继续 | 原始缺口、盲接提问或缺口报告、未执行依赖动作的记录及文件差异 |
| 主动交接 | 给交接者一项新的用户纠偏或已验证操作步骤，再明确请求“准备换新对话，更新文档治理”；只更新有变化的原职责文件，稳定知识与临时现场各归其位，HANDOFF 指路 | 实际 diff、来源归属、简短回执；分别标明已保存、已核对、实测接续或未测；无同义状态表、无自动清理 |

第三项验证的是“准备交接”的行为，可以由独立交接者执行并再交给另一位无历史接手者；同一个执行者看过全部输入后自测只能算局部检查。缺口案例不需要拿走所有线索、让新 AI 漫无目的猜测，评价重点是准确定位缺失和只暂停依赖动作。环境或登录态只能在实际核实后报可用，旧证据只能证明当时成功。

隔离接续通过不代表真实 SSH、网站后台登录态或跨工具调用均已验证。将离线示例、自有测试环境和实际原生客户端的结果分别报告；未经授权不要为验收连接外部系统。

## 历史增长的对照检查

修改事件捕获或恢复的性能时，准备内容相同、规模不同的单流和多会话合成历史，比较固定基线与候选的 `capture/reconcile/status/resume`。记录实际平台／Python 版本、事件与回执数、重复次数、耗时、JSON 读取次数和读取字节；分别报告准备开销与被测命令，不把热缓存的一次结果称为普遍收益。

除了速度，还应对照捕获内容、当前来源、待核对／未解决事件、未知尾部、过期回执及截断提示等语义结果；随机 ID 和时间戳只在确属无关字段时规范化。重复事件、乱序／迟到摘要、错误 `no_change`、过期来源、写中变化及旧记录兼容按相关回归检查。写入前后的变化核对不能为减少读取而省掉。

只声称实际测量到的改进，注明仍随历史量增长的路径和未测范围。减少重复读取不等于磁盘文件不再增加，也不授权归档、压缩或删除；性能测试本身不触发文档清理。基准不能替代操作盲接，操作盲接也不能证明历史规模下的性能。

## 文档收敛挑战

在隔离副本中准备一份详细但已被替代的旧方案、一份当前决定及证据、一条仍未解决的问题。先锁定应保留的当前选择、用户约束、旧方案被否决的原因、未决项和证据，由验证者明确发起整理请求，再按 [生命周期规则](../00_PROJECT_CONTROL/DOCUMENT_LIFECYCLE.md) 收敛入口和相关材料。给独立 AI 正常入口，要求说明下一步、依据及仍不能宣称完成的事项。

通过需同时满足：当前选择正确、未决项没有丢失、否决原因可追溯、没有把历史测试当成当前验收。若记录读取量，保留实际读取路径和工具输出，不能用仓库文件数推算 token 或效率。这个定向挑战可替代本次不相关的故障演练，不能据一次合成案例宣称长期收益。

再设置一份无法由现有材料裁定的要求冲突，例如两份都标为已确认的合同对同步/队列有不同要求，却没有替代决定。独立 AI 应提出一条带来源、建议和影响的具体问题，保留两份材料，只暂停依赖此选择的动作。可裁定的前一案例不应重复询问已确定的要求。这样同时检验“该问时问”和“无需问时继续”，而不把任何不确定性都上交用户。

## 接力故障挑战

在隔离 Git 副本中登记一个依据 ctx-001 的执行任务，并准备负责人失去聊天历史后的检查点。当前权威来源明确“文档清理只由用户主动请求”，但旧派工漏交此约束。补充 ctx-002 和针对原执行会话的纠偏，保留为 `recorded`。让旧执行结果包含正常功能和不符合新依据的自动归档动作；同时保留一项尚未验证的运行假设。模拟执行现场只能提供最后观察、无法据此断定当前进程停止。不要把正确答案塞进恢复摘要。

给无历史的接手者正常入口及“继续处理这个任务”的请求。通过条件预先封存：从来源找回硬约束；查询原会话和交付而非重复派工；不把纠偏写成已送达；不接受旧版本回执；具体指出可复用和受影响范围；假设继续标未证实；不触发或询问文档清理。遇到现场不可查询时保留未知，继续能够独立完成的审查，不伪造停止或验收事实。保存输入、所读材料、实际回答和动作，不能只检查是否复述协议。

再运行机器负例：原始快照被改写而登记 hash 未变；回执指向旧版本；纠偏缺送达／采用证据；检查点绑定错误会话。均应报出对应问题。旧任务不含 `context` 时应保持兼容，并如实报告新协议未覆盖。

若要声称 Codex → Claude Code 已可接力，需另做实际跨工具调用：把明确版本的材料放入执行者能访问的独立目录；让执行者按快照给出关键选择或小结果；通过具体 session 续送纠偏并观察采用，或对一次性旧交付核对后重交。默认使用现有授权与权限，不放宽工具安全配置。记录实际 CLI 版本、方式、材料 hash、结果、独立验收和未测部分。独立 Agent 合成演练不替代真实跨工具证据；真实 print/resume 也不等于已测压缩 hook、进程中断恢复或所有调用方式。

## 在真实工作里观察收益

接下来的实际任务和自然发生的换会话中，由 AI 随任务记录以下事实；无需建立定时提醒或额外监控任务。

| 观察 | 记录方法 |
|---|---|
| 重复劳动 | 哪个已完成动作被重新提出或执行、有没有花费时间或触发外部操作；正常回归检查不算重复劳动 |
| 用户纠偏 | 用户因遗忘、状态错误、误读范围而纠正 AI 的次数和原因；用户改变需求不计入 |
| 接手成本 | 从读入口到找到正确下一步所需时间、阅读文件数；缺时间记录写未知 |
| 维护成本 | AI 为同步治理花费的时间、修改文件数，是否同一事实要改多处；区分业务开发时间 |

有治理前的记录就对照；没有就先建立观察基线，不能宣称“减少了多少”。两三次工作样本只能说明观察到什么，不能证明所有项目都有效。若没有减少解释，却明显增加维护负担，应删除重复状态、合并入口或缩小记录范围；不要靠增加模板应对。

## 用户只看简短结果

AI 将完整记录放在映射的 `evidence_dir`，项目 STATUS 链接结果，不复制明细。向用户报告以下四项即可：

```text
治理检查：实际完成了哪些检查，哪些未测。
是否帮上忙：本轮观察到的正确接手、重复劳动或纠偏；没有对照就明说。
发现与处理：具体失败点、已修复内容、仍未解决的限制。
需要你决定：只有无法从现有目标、事实和授权判断的事项；没有就写无。
```

单次试验记录包含日期、被测提交／文档版本、环境、每项实际结果与证据、观察值、修复及未测范围。通过与否由预先写明的条件和实际证据判断，不要求用户替 AI 检查每个文件。

母仓库发布验收见[验收标准](TEST_CASES_AND_ACCEPTANCE_v1.md)，委派与恢复边界见[执行合同](../02_TECH/HARNESS_CONTRACT.md)。
